# 知识库 08：开源工程化（ThirdLink 的首个开源项目）

> 归属阶段：阶段 5 之后 + 阶段 7。ThirdLink 是你的第一个开源项目，首要目标是完整走一遍工程化流程。

## 一、开源项目生命周期

初始化 → 开发 → 发布 → 维护。四个阶段各有清单，按顺序走。

## 二、阶段 A：初始化（1-2 天，写代码前先做）

1. **License（先定，后写代码）**
   - 推荐 MIT：简单、允许任何人使用/修改/商用，最适合练手项目；
   - 备选 Apache-2.0：多一条专利条款，企业更友好；
   - GPL 慎选：传染性强，会限制别人商用你的代码。
2. **README.md**（项目的门面，结构模板见下）
3. **.gitignore**（build/、.cache/、CMakeUserPresets.json、*.log 等产物）
4. **.gitattributes**（换行符策略：* text=auto + *.sh text eol=lf——跨平台必备，防止 LF/CRLF 混乱）
5. **.editorconfig**（跨编辑器统一缩进/换行）
6. **git init + 分支规范**：main（主分支）+ feature/xxx（功能分支）
7. **提交规范：Conventional Commits**
   - feat: 新功能 / fix: 修复 / docs: 文档 / refactor: 重构 / test: 测试 / chore: 杂务
   - 例：feat: add inverse kinematics solver

## 三、阶段 B：开发流程（贯穿整个项目）

1. 功能开发走分支：feature/xxx → PR → merge 到 main；
2. Issue 模板 + PR 模板（GitHub 仓库设置里配）；
3. CI（GitHub Actions）：每次 push 自动编译 + 跑测试；
4. 代码质量门禁：clang-format（格式化）、clang-tidy（静态检查）、编译 0 警告；
5. Doxygen 注释公共 API（这样才有 API 文档可看）。

## 四、阶段 C：发布（首个 release）

1. **语义化版本 SemVer**：v0.1.0（主.次.修）
   - 0.x 阶段：API 可以随意变，不承诺稳定；
2. CHANGELOG.md：记录每个版本的变化；
3. git tag v0.1.0 + GitHub Release（写 release notes）；
4. 打包（可选）：CPack 生成安装包。

## 五、阶段 D：维护

1. CONTRIBUTING.md（告诉别人怎么参与）；
2. CODE_OF_CONDUCT（社区行为准则，GitHub 有模板）；
3. 定期更新依赖、回复 issue；
4. 诚实声明：README 里写清楚这是学习项目。

## 六、README 结构模板

    # 项目名
    一句话描述
    ![截图](...)
    ## 特性（简洁列表）
    ## 构建（一键命令）
    ## 使用方法
    ## 项目结构
    ## 路线图（Roadmap）
    ## License
    ## 贡献指南（链接 CONTRIBUTING）

## 七、工具清单与定位

    git             版本控制：一切的基础
    GitHub          托管 + Issue/PR/CI/Release 平台
    GitHub Actions  CI：自动编译测试
    SemVer          版本号规则
    Doxygen         API 文档
    clang-format    格式化
    clang-tidy      静态检查
    CPack           打包

## 八、开源礼仪要点

- 先写 README 再发布（没人看得懂的项目不会被 star）；
- 提交信息用英文（国际社区惯例）；
- 响应 issue 用礼貌语言，不承诺做不到的事；
- 0.x 版本期不要宣传稳定 API。
